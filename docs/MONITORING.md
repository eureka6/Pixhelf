# 系统监控

管理员可以在“系统信息”查看 CPU、内存、负载、存储和网络。程序后台采样不依赖网页是否打开，图库与数据目录的大小另行按需统计并缓存。

| 来源 | 内容 | Pixhelf 停止期间 |
| --- | --- | --- |
| Linux `/proc` | 当前 CPU、内存、运行时长、1 / 5 / 15 分钟负载及网卡累计流量 | 内核继续维护，重启程序后直接读取 |
| 系统已有的 sysstat / sar 日志 | 带采样间隔的网卡收发速率 | 系统原有记录可用于补充停机时段 |

## 历史曲线

“1 分钟”“5 分钟”使用 Pixhelf 实时采样。最近 5 分钟的高频记录保存在 `CACHE_DIR/system/history.jsonl`，重新打开页面或重启程序后恢复尚未过期的数据。

“24 小时”读取系统已有记录。程序查找 `/var/log/sysstat/`、`/var/log/sa/` 下的 `saDD` 或 `saYYYYMMDD`，通过 PATH 中已有的 `sadf` 只读导出；每分钟检查一次，最多读取最近修改的 4 个文件，保留最多 1441 个采样点。

曲线提示显示原始平均区间，如“10 分钟均值”；缺少记录和系统重启处断开。历史记录只覆盖网络，CPU 与内存显示当前状态。格式与单位见上游 [sadf](https://github.com/sysstat/sysstat/blob/master/man/sadf.in) 和 [sar](https://github.com/sysstat/sysstat/blob/master/man/sar.in) 文档。

## 部署环境

没有 `sadf` 或可用日志时，“24 小时”显示“暂无系统记录”，实时信息仍可使用。Pixhelf 不会安装 sysstat 或启用采集任务；内核累计数据也无法还原停机期间每个时刻的流量。

Docker 读取的是容器可见的内核接口与日志。精简镜像不附带 `sadf`，通常只提供实时信息和累计数据；外部提供日志时，应确保其主机和网络命名空间与被监控网卡一致。读取设有超时、大小和主机身份检查，异常不会阻塞实时采样。
